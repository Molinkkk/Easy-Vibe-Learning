# Task03 需求说明：电商素材工作台

> 版本：V0.1（课程原型范围）  
> 状态：待业务验证  
> 课程来源：Datawhale Easy-Vibe《动手做出原型》  
> https://datawhalechina.github.io/easy-vibe/zh-cn/stage-1/building-prototype/

## 1. 给谁用、在什么场景下用

**目标用户（课程案例）：** 负责抖音电商等平台商品上新的电商运营人员。

**使用场景：** 运营需要为一批待上架商品准备商品主图、标题和卖点文案。商品基础信息、白底图或场景图、历史参考素材可能分散在不同位置；运营希望先快速形成可筛选、可修改的内容草稿，再决定是否进一步精细制作。

**业务依据与限制：** 上述场景和痛点来自 Datawhale 教程中的课程案例描述。本仓库目前没有独立完成真实运营人员访谈，因此不能将课程案例写成团队自己的访谈结果。正式面向真实用户前，需要补充访谈或实际业务观察。

## 2. 要解决的问题

当电商运营需要为多个商品准备上架素材时，他们希望能够集中提交商品信息和参考素材，快速得到可编辑的商品主图草稿、标题和卖点文案，以减少逐个从零制作内容的重复工作。

当运营发现某套主图、标题和文案方案效果较好时，他们希望能够保存并再次查找、套用和修改，避免方案散落在聊天记录或历史商品内容中而难以复用。

**本原型优先验证的两个问题：**

1. 批量准备商品图文草稿是否能让运营更方便地完成初稿筛选和修改。
2. 将一整套图文方案保存为模板，是否能让后续商品内容制作更容易复用。

## 3. 第一版只做的核心流程

### 核心流程 A：生成商品图文草稿

1. 运营进入素材工作台。
2. 填写商品基础信息：商品名称、类目、品牌、材质、尺寸、颜色等。
3. 上传商品白底图或简单场景图，并可添加历史参考图或参考链接。
4. 可选择逐条填写或通过 Excel 导入多条商品信息（原型阶段可先用样例数据模拟批量导入）。
5. 提交生成请求。
6. 页面展示每个商品对应的主图草稿预览、商品标题和 1–2 句卖点文案。
7. 运营可以查看并编辑标题、文案，筛选需要保留的草稿。

### 核心流程 B：保存和复用方案

1. 运营从已生成的内容中选择一套主图、标题和文案。
2. 为方案填写模板名称并添加标签。
3. 保存到模板列表。
4. 在模板列表中查找并选择模板。
5. 将模板应用到新商品草稿，并允许运营继续修改标题和文案。

**原型实现说明：** Task03 的重点是可交互产品原型。若尚未接入真实生成模型，允许使用明确标注的模拟结果演示页面流程；不得将模拟生成描述为真实 AI 服务已经接入。真实 AI 图片和文案生成能力留待后续课程阶段实现。

## 4. 第一版不做什么

为控制原型范围，第一版暂不实现：

- 商品自动上架到抖音、淘宝等外部平台。
- 店铺授权、多店铺统一管理和账号权限体系。
- 商品自动调价、活动排期和库存管理。
- 商品销售数据分析、广告投放和效果归因。
- 完整的视频生成、剪辑和发布工作流。
- 真实生产级 AI 图片生成与文案生成 API（留待后续课程阶段）。
- 复杂的团队协作、审批和企业级素材权限管理。
- 生产级 Excel 大批量导入、异步任务调度和高并发处理。

## 5. 怎样算验证成功

以下是本次原型的**可检查验收标准**，不是已经测得的业务收益：

| 验收点 | 可观察的通过条件 |
|---|---|
| 商品信息录入 | 能填写示例商品的基础信息，并展示已录入内容 |
| 图片素材输入 | 能选择图片并在页面中预览；不支持的格式有明确提示 |
| 草稿结果展示 | 点击生成后能看到对应商品的主图预览、标题和卖点文案；若为模拟数据，页面明确标注 |
| 内容编辑 | 能修改标题和卖点文案，并在界面中看到修改结果 |
| 模板保存 | 能将一套图文方案命名并保存 |
| 模板查找与套用 | 能在模板列表找到已保存模板，并将其应用到另一条商品草稿 |
| 多页面交互 | 导航、返回、主要按钮均可操作，不出现无响应入口 |
| 异常与状态反馈 | 至少覆盖空输入、未选择素材、生成中、生成完成和失败提示等状态 |
| 可演示性 | 按 README 步骤可在本地启动，并从头到尾演示上述核心流程 |

**业务价值验证（后续进行）：** 需要邀请目标用户完成相同的商品素材准备任务，观察操作步骤、完成时间、修改次数和模板复用情况，再判断是否真正提升效率。本课程原型本身不能证明已经产生业务效率提升。

## 6. 还没确认的问题

以下事项目前没有课程材料或真实访谈提供确定答案，原型阶段先采用可替换的设计假设，后续需要向业务用户确认：

1. 运营每批通常处理多少个商品？Excel 模板需要哪些必填列？
2. 商品图片有哪些格式、尺寸、数量和大小限制？
3. 参考图和参考链接是否允许来自外部平台？是否涉及版权或授权要求？
4. 生成的商品主图需要遵守哪些平台规范、品牌规范和文字排版要求？
5. 标题关键词、字数和禁用词是否有平台或店铺规则？
6. 模板需要按店铺、商品类目、品牌还是活动进行分类？
7. 模板是否需要版本记录、共享或权限管理？
8. 用户如何判断生成结果“可用”？由谁审核，是否需要保留修改前后的版本？
9. 真实生成流程的可接受等待时间和失败后的重试方式是什么？
